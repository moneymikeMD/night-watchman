## capability-ladder

Decide where repeated work's knowledge is kept and where it runs, as two separate questions. Use when someone proposes adding a new agent, when asked "should this be a script, an agent or a skill", or when the main thread does the same work inline a second time with no fixed home for it.

## diagnose-and-pr

Diagnose one firing failure signal (an alert, a failed check, a monitoring finding) against this repo with the disciplined loop (a red command before any theory), then open a draft PR fixing it on a feature branch. Never pushes to main, never remediates a live host. Use when a sweep, webhook or the owner hands over a concrete failure to debug and fix, or when the owner wants a failing behaviour diagnosed rather than a one-line answer. Pass the signal as the argument - what fired, when, and any first-pass triage.

## grill

Stress-test a plan, design, or decision by interviewing the owner in rounds until nothing is left assumed, then hand the settled decisions to to-issues. Use when the user says "grill me" or "grill this plan", asks to poke holes in an idea or find its weak spots before committing to it, or a to-issues decision ticket needs an owner conversation.

## handoff-docs

Writing a handoff note for whoever picks this up next — a fresh session, or a different person. Use when the user says "write up where we left off", or when unfinished work is moving to another machine or person.

## session-start

The opening move for a fresh session in a project running this plugin's unattended-operations model — orient from docs/, verify every awaiting-deployment ticket against reality, and fan startable work out to pinned-model subagents in parallel. Load when the user says "start a wave", "run a wave", "start on the next open tickets", "pick up where we left off", "what can be worked on", or opens a session with no specific task — and before dispatching any wave, even one whose tickets the user has already named.

## shell-scripting

Shared-lib conventions and the shipped-bug rules for scripts/ — bash 3.2 limits, subshell die, pipe_ok, secrets in argv, and structural network isolation in selftests. Load before writing or reviewing anything in scripts/.

## tickets-protocol

The docs/ routing table and the ticket workflow — status-is-a-directory-move (or a tracker transition, if one is adopted), the frontmatter/field contract, body-vs-progress-note rules, and the UNVERIFIED discipline. Load for ticket filing, ticket transitions, or any durable-knowledge capture.

## to-issues-mine

Mine a settled planning, grilling, or design conversation into a decision-list JSON conforming to work-order's decision-list/FORMAT.md — the mining half of to-issues, split so that ticket authoring lives in work-order's emit-tickets skill instead of here. Use whenever a grilling session ends and the decisions need to leave the conversation as data, before anything decides how they become ticket files.

## to-issues

Turn a finished planning, grilling, or design conversation into independently-workable tickets as frontmatter Markdown files on disk, so the session can be closed and the work picked up cold by parallel agents in git worktrees. Use this whenever a grilling session ends, whenever the user says "turn this into tickets/issues/a work log", "write this up as separate pieces of work", "break this up into work I can parallelise", or after any long discussion that settled a bunch of decisions and now needs to survive the context window. Also use it when a plan already exists but the tickets are too coupled or too vague for an agent to execute without asking questions.

## wave-trail

Keep an append-only decision trail for an unattended or dispatch-provider wave (one row per fork, pivot, revert, or verified unit), audit it against the transcript once the wave is done, and have a second-tier reviewer write an Attention section for the human. Use when a wave is dispatched through a dispatch provider, or any run the owner is not watching live.

## wrap-up

Wrap up a session — ask what it left behind and run only the session-end mechanisms that apply (reflector, librarian or session-harvest, handoff-docs, memory). Use when the user says "wrap up", "we are done for today", "end the session", or before closing a session that did real work.
