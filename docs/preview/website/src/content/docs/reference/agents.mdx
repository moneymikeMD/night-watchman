## branch-resync

Brings open branches up to date after their base moved — merges the base into each one (a merge commit and a normal push, never a rebase), resolves conflicts keeping both sides' intent, regenerates lockfiles and generated files instead of hand-merging them, runs the repo's hooks and required checks, pushes, and reports each new head plus any contract the incoming commits impose on the branch's code. Use whenever main moves while branches are still open, and whenever land-branch stops on a conflict against the current base.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## librarian

Maintains a project's docs/ (or knowledge-base) directory and its tickets, per the tickets-protocol skill. Use for filing tickets, moving tickets between stages, recording decisions, updating known-issues, capturing durable knowledge, and retiring under-used scripts flagged by the cost-review skill. Runs the issues.py linter before any ticket change; commits docs changes directly, and retirement commits via ai-toolkit's script-retire.sh + land-branch.sh.

- **Model:** haiku
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## pr-shepherd

Takes one finished branch from local green to merged — runs the checks CI will run before the first push, pushes, opens the PR, watches its checks, reads the failing job's log on red, fixes what is inside the branch's scope, and merges on green through pr-land.sh when the repo's recorded landing policy lets an agent merge its own PR. A check that ran and failed is fixed or reported, never bypassed. Use for any branch that lands through a pull request rather than land-branch.sh's direct merge, and whenever a PR's CI is red or a PR is waiting to be merged once green.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## reflector

Read-only sonnet agent that mines the current session's transcript for durable corrections and proposes routed skill/agent edits, output as Accepted / Rejected / Backlog tables. Use when the user says "reflect", or after a session where the owner corrected the agent. Never edits anything itself — the owner approves row by row. Pairs with the cost-review skill: that skill recommends cost changes, this one recommends behavior changes.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob

## researcher

Finds external facts on the web — software versions, upgrade paths, provider/collection maturity, feature support matrices, licences. Use when a decision needs a fact that lives outside the repo and the project's own systems. Returns a terse sourced table; never writes to the repo, never touches a host.

- **Model:** sonnet
- **Tools:** WebSearch, WebFetch, Read

## script-author

Writes and modifies the reusable operational scripts in scripts/ in the lane the brief names, or picks one — capture (the default; commands already run live saved as one small script, or a bounded edit with the diagnosis supplied) or hardened (unattended, destructive, the shared library, or earned by use). Use whenever operational work needs to land as a script, a new API wrapper is needed, or an existing script needs a change. Runs shellcheck locally; never runs scripts against live systems.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## script-reviewer

Reviews a hardened-lane script in scripts/ (unattended, destructive, the shared library, or earned by use) against the shell-scripting review checklist and this project's shipped-bug history, before it runs against a live system. Capture-lane scripts ship on the author's shellcheck and bash -n; this agent reviews one only on owner or orchestrator request. Read-only plus shellcheck; reports findings, changes nothing.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash

## spec-reviewer

Reviews a finished ticket branch against its own ticket, not against style — runs the repo's required checks and issues.py scope, then reports missing or partial Solution items, behaviour the ticket did not ask for, and implementations whose verify would pass without the intended effect. Read-only; never edits, never spawns agents, never runs verify against a live system. Use before land-branch on any agent-executed ticket.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash

## wave-supervisor

Runs a dispatched wave to the end without the owner polling it — watches every worker through the dispatch provider, reviews and lands each finished branch, closes landed workspaces, and starts the next queued ticket on the machine with the most free memory. Returns only for a decision (a worker's question, a conflict, a failed gate, a dead or stalled worker) or when the queue is empty and every worker has settled. Launch once per wave, in the background, right after the first dispatch start; not needed when the dispatch provider is `workflow`.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash
