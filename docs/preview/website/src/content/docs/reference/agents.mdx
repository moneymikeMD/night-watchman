## branch-resync

Brings open branches up to date after their base moved — merges the base into each one (a merge commit and a normal push, never a rebase), resolves conflicts keeping both sides' intent, regenerates lockfiles and generated files instead of hand-merging them, runs the repo's hooks and required checks, pushes, and reports each new head plus any contract the incoming commits impose on the branch's code. Use whenever main moves while branches are still open, and whenever land-branch stops on a conflict against the current base.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## cost-reviewer

Runs the end-of-wave cost review from the project's cost ledger (default docs/cost.md's ledger, see that doc for the path convention) — appends this wave's row with scripts/claude-cost.py, compares it to the previous wave, optionally cross-checks against a metrics backend if one is configured, and reports the delta plus a verdict on whether last wave's adopted recommendation moved the number it targeted. Read-only outside the ledger file: it recommends changes to agents, skills, hooks, CLAUDE.md and settings but never makes them itself, and never runs anything against a live host.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash

## epic-closer

Decides what an epic (or the whole backlog) still needs to reach Completed and drives it there — fills ticket fields it can derive from the repo and the ticket's own text, moves fully filed tickets out of triage, verifies awaiting-deployment tickets against reality with read-only checks from their verify blocks, transitions what the evidence supports with the evidence in the comment, and closes the epic when no child is left. Ends with the epic closed or a residue list naming the single thing each remaining ticket waits on. Use when asked what is left on an epic, why tickets sit in triage, or to get an epic to Completed.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## librarian

Maintains a project's docs/ (or knowledge-base) directory and its tickets, per the tickets-protocol skill. Use for filing tickets, moving tickets between stages, recording decisions, updating known-issues, capturing durable knowledge, and retiring under-used scripts flagged by cost-reviewer. Runs the issues.py linter before any ticket change; commits docs changes directly, and retirement commits via ai-toolkit's script-retire.sh + land-branch.sh.

- **Model:** haiku
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## pr-shepherd

Takes one finished branch from local green to merged — runs the checks CI will run before the first push, pushes, opens the PR, watches its checks, reads the failing job's log on red, fixes what is inside the branch's scope, and merges on green through pr-land.sh when the repo's recorded landing policy lets an agent merge its own PR. A check that ran and failed is fixed or reported, never bypassed. Use for any branch that lands through a pull request rather than land-branch.sh's direct merge, and whenever a PR's CI is red or a PR is waiting to be merged once green.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## reflector

Read-only sonnet agent that mines the current session's transcript for durable corrections and proposes routed skill/agent edits, output as Accepted / Rejected / Backlog tables. Use when the user says "reflect", or after a session where the owner corrected the agent. Never edits anything itself — the owner approves row by row. Pairs with cost-reviewer: that agent recommends cost changes, this one recommends behavior changes.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob

## researcher

Finds external facts on the web — software versions, upgrade paths, provider/collection maturity, feature support matrices, licences. Use when a decision needs a fact that lives outside the repo and the project's own systems. Returns a terse sourced table; never writes to the repo, never touches a host.

- **Model:** sonnet
- **Tools:** WebSearch, WebFetch, Read

## script-author-lite

Captures commands already run live in a session into one small, bounded, non-privileged script under scripts/. Use for a mechanical write-up of a proven command sequence — not for new design work, and never for anything touching a credential, a live host, or sudo. Refuses and hands back to script-author on any of those.

- **Model:** haiku
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## script-author

Writes and modifies the reusable operational scripts in scripts/, following the project's shared shell-library conventions. Use whenever operational work needs to land as a script, a new API wrapper is needed, or an existing script needs a change. Runs shellcheck locally; never runs scripts against live systems.

- **Model:** sonnet
- **Tools:** Read, Edit, Write, Grep, Glob, Bash

## script-reviewer

Reviews shell (and Python-lane) scripts in scripts/ against this project's shared-library conventions and shipped-bug history. Runs by default only for scripts touching credentials, hosts, sudo, or scripts/lib/* — every other script ships on the author's lint+selftest, and this agent runs only on owner/orchestrator request. Read-only plus shellcheck; reports findings, changes nothing.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash

## spec-reviewer

Reviews a finished ticket branch against its own ticket, not against style — runs the repo's required checks and issues.py scope, then reports missing or partial Solution items, behaviour the ticket did not ask for, and implementations whose verify would pass without the intended effect. Read-only; never edits, never spawns agents, never runs verify against a live system. Use before land-branch on any agent-executed ticket.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash

## wave-supervisor

Runs a dispatched wave to the end without the owner polling it — watches every worker through the dispatch provider, reviews and lands each finished branch, closes landed workspaces, and starts the next queued ticket on the machine with the most free memory. Returns only for a decision (a worker's question, a conflict, a failed gate, a dead or stalled worker) or when the queue is empty and every worker has settled. Launch once per wave, in the background, right after the first dispatch start; not needed when the dispatch provider is `workflow`.

- **Model:** sonnet
- **Tools:** Read, Grep, Glob, Bash
