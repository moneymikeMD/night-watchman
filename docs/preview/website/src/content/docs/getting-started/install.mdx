Moved verbatim from the ["Install" section](https://github.com/moneymikeMD/night-watchman/blob/main/README.md#install) of the project README.

```
claude plugin marketplace add moneymikeMD/moneymike-plugins
claude plugin install night-watchman@moneymike-plugins
```

From a local checkout instead (development, or an air-gapped host), load the
plugin directory directly:

```
claude --plugin-dir /path/to/night-watchman
```

night-watchman depends on one other plugin: [work-order](https://github.com/moneymikeMD/work-order), which carries
the ticket contract and its `issues.py`. Both plugins are published by the
`moneymike-plugins` marketplace, so the marketplace install brings the
dependency with it. A plugin loaded with `--plugin-dir` has no plugin-list
entry, so `scripts/work-order-root.sh` finds work-order through
`$WORK_ORDER_ROOT` or a sibling checkout instead. After a marketplace install,
check the `errors` field, not the exit code — a dependency that cannot resolve
still reports `ok` and exits 0:

```
claude plugin list --json \
  | jq '.[] | select(.id == "work-order@moneymike-plugins") | {version, errors}'
```

Neither form wires up a provider. Enable an optional layer
(below) by copying its directory into your project and following that
layer's own section.

To declare which providers your repo uses, copy the template and commit it:

```
mkdir -p .night-watchman
cp templates/night-watchman.config.toml .night-watchman/config.toml
providers/lib/provider.sh doctor
```

Every value in that template is already the built-in default, so this step
changes no behaviour on day one. It is worth doing anyway: it puts the
answer to "what does this repo talk to?" in the repo's history, where a
change to it shows up in a diff.

On a fresh tree today `doctor` reports `not-installed` for all four kinds.
That is expected, not a fault: the contract has landed, and the
implementations are still being ported into `providers/` (see the table in
[`providers/README.md`](../../guides/providers/)). `IMPL` and `ORIGIN` are
still the real answers — what the kind resolves to, and which rule
decided — and both are worth reading before the implementations arrive.
