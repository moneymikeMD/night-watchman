# throwaway scratch project, same template as NWM: To Do/In Progress/Done
# only). Non-mutating despite the POST verb — the request body is a name
# list, not a document to persist (a recipe proven live elsewhere). This is the ground
# truth for the /workflows/update request shape: note workflow objects in
# `.workflows[]` are keyed by a plain string `name` (NOT nested under an
# `{name, entityId}` id object the way GET /workflow/search's OWN read
# shape nests it — see workflow.search.nwm.txt/.lab.txt for contrast), and
# `.workflows[].id` is itself a plain string (the workflow's entityId).
# `ruleKey`/`permissionKey` values under actions[]/validators[] were
# redacted by the wrapper's own redact_json (both names contain "key",
# which the wrapper's credential-name heuristic treats as secret-shaped —
# these are Jira-internal rule identifiers, not credentials, but the
# wrapper cannot tell the difference and errs toward redacting). This
# script therefore drops actions/validators/triggers/links entirely when
# reconstructing an existing transition for an update body, rather than
# attempting to round-trip a value it can only ever receive already
# blanked. No other redaction applied. Nothing else trimmed.
